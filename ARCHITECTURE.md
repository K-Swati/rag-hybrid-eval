# Architecture

How the code is organised and why. For how to run it, see the [README](README.md).

## The idea in one picture

```
                         ┌────────── Postgres (single source of truth) ──────────┐
                         │  sales, production_batches, products, distributors…   │
                         │  documents (policies as markdown)                     │
                         └───────┬───────────────────────────────┬───────────────┘
                                 │ read-only SQL                 │ export at start-up
                                 │                               ▼
question ─▶ Router ──── sql ─────┤                     markdown knowledge base (14 docs)
                │                ▼                               │ chunk + index
                │        SqlWriter ─▶ guards ─▶ rows             ▼
                └────── docs ──────────────────────────▶ hybrid search (dense + BM25 + rerank)
                                 │                               │
                                 ▼                               ▼
                           narrate rows                 generate from passages
                                 └──────────────┬────────────────┘
                                                ▼
                                Reply (same shape for both paths)
```

Numbers are never answered from text, and policies are never answered from SQL. Each kind of question goes to the tool that answers it reliably. Both paths read from the same database, so they can't drift apart.

## Layers

Each layer may import only from the layers below it. `tests/test_architecture.py` fails the build if an import breaks this rule.

```
┌───────────────────────────────────────────────────────────────────────────┐
│ Interfaces   api/ (app, routes, schemas, jobs, ui/)   __main__ (CLI)      │  input/output only
├───────────────────────────────────────────────────────────────────────────┤
│ Services     wiring.py     build every component from Settings            │  composition + orchestration
│              assistant.py  route -> SQL path or document path -> Reply    │
│              pipeline.py   document path: chunk, index, retrieve, generate│
│              evaluate.py   benchmark: routing, SQL, retrieval grid        │
├───────────────────────────────────────────────────────────────────────────┤
│ Warehouse    warehouse/    seed data, policies, export to markdown,       │  the company's data
│                            Postgres access (catalog, rows, read-only query)│
├───────────────────────────────────────────────────────────────────────────┤
│ Core         core/         router, text_to_sql, sql guard, chunking,      │  pure building blocks
│                            embeddings, retrieval, generate, metrics       │
├───────────────────────────────────────────────────────────────────────────┤
│ Config       config.py     Settings.from_env                              │  read once, at the edge
└───────────────────────────────────────────────────────────────────────────┘
```

| Layer | Owns | Must not |
|---|---|---|
| Interfaces | HTTP and CLI parsing, response shapes, the background benchmark job, the UI | contain routing, SQL or retrieval logic |
| Services | wiring components together, choosing the path, running the benchmark | know about HTTP or the CLI |
| Warehouse | what the data is, how it is stored, how it becomes documents | import services, interfaces or config |
| Core | algorithms with no knowledge of this company's database | import the warehouse or anything above it |
| Config | the list of environment variables and their defaults | be read anywhere except the entry points |

`core` has no knowledge of Postgres or of this company. The rule SQL writer gets its product, region and plant names through a `Vocabulary` that the services layer builds from the database.

## Module map

```
db/init/
  01_schema.sql         tables, keys, and COMMENTs (the data dictionary)
  02_seed.sql           generated by `python -m rag_eval db seed-sql`
  03_reader_role.sql    rag_reader: SELECT only, read-only by default, 5 s timeout
rag_eval/
  config.py             Settings: every environment variable in one place
  core/
    router.py           Route; KeywordRouter (offline), OpenAIRouter
    text_to_sql.py      SqlPlan, Vocabulary; RuleSqlWriter (offline), OpenAISqlWriter; narrate_result
    sql.py              check_select (guard), QueryResult, same_result, rupee formatting
    chunking.py         fixed, recursive and heading-aware chunking
    embeddings.py       HashingEmbedder (offline), OpenAIEmbedder
    retrieval.py        Qdrant vector index, BM25, reciprocal rank fusion, reranker, trace()
    generate.py         ExtractiveGenerator (offline), OpenAIGenerator
    metrics.py          hit rate, precision, MRR, nDCG, groundedness
  warehouse/
    seed.py             deterministic demo data -> rows -> SQL
    knowledge.py        the 8 policies and SOPs
    export.py           rows -> markdown documents (one ## section per record)
    db.py               Warehouse: catalog(), rows(), fetch_all(), query(); init_database()
  pipeline.py           RagPipeline (one chunking strategy), PipelineRegistry (one per strategy, lazy)
  assistant.py          Assistant.ask() -> Reply; knowledge-base and vocabulary loaders
  evaluate.py           run_benchmark(), write_reports()
  wiring.py             build_components(settings) -> Components
  api/                  create_app(), routes, schemas, EvalJob, ui/index.html
  __main__.py           CLI: ask | eval | serve | db
```

## Extension points

| To add | Implement | Register in |
|---|---|---|
| a router (another model, a classifier) | `Router`: `name`, `route(question) -> Route` | `wiring.make_router` |
| a SQL writer | `SqlWriter`: `name`, `write(q) -> SqlPlan \| None`, `narrate(q, plan, result) -> str` | `wiring.make_writer` |
| a markdown search engine | a pipeline with `ask(question, mode, k, trace) -> Response`, built from the `KbDoc` list | `wiring.build_components` |
| an embedding model | `Embedder`: `name`, `dim`, `embed(texts)` | `core/embeddings.get_embedder` |
| an answer generator | `Generator`: `name`, `generate(question, hits) -> Answer` | `core/generate.get_generator` |
| a chunking strategy | `fn(Document) -> list[Chunk]` | `core/chunking.STRATEGIES` |
| a table | DDL with COMMENTs in `01_schema.sql`, rows in `seed.py`, and a section in `export.py` if it holds text | regenerate `02_seed.sql` |

`python -m rag_eval db export-md` writes the knowledge base as `.md` files. That is the hand-off point for an external markdown search service: index those files and plug the service in as the document pipeline.

## Request flow: `POST /ask`

```
routes.ask ── AskRequest validated (422 on bad input)
  ▼
Assistant.ask
  ├─ route = Router.route(q), or the user's forced choice
  ├─ sql:  SqlWriter.write -> None? fall back to docs with a note
  │        Warehouse.query: check_select -> read-only txn -> timeout -> rag_reader role
  │        SqlWriter.narrate(rows) -> answer
  └─ docs: PipelineRegistry.get(strategy).ask(mode, k, trace)
  ▼
routes.ask adds document titles and, for gold questions, a live check
(the reference query is run, or the key phrase is looked up in the sources)
```

## Decisions

| Decision | Why |
|---|---|
| Postgres as the one source; documents are exported from it | numbers and text cannot disagree; one place to change data |
| SQL for numbers, RAG for text | retrieval cannot add up 8,573 rows; SQL cannot explain a root cause |
| Offline implementations of every model-backed part | runs and tests with no key; the benchmark is reproducible |
| Rule writer returns `None` instead of guessing | a wrong number is worse than "I can't"; the UI says why |
| Four separate SQL guards | any one can fail (prompt injection, a guard bug) without data being changed |
| Data dictionary in Postgres COMMENTs | the UI and the SQL prompt read the same truth, kept next to the schema |
| One `##` section per record in exports | heading chunking then gives one chunk per product, supplier or incident |
| Benchmark compares results, not SQL text | many queries are correct; only the answer matters |
